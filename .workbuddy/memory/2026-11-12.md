## 修复：规划分区对话框「容量输入框没有颜色」（src/ui/one_click.rs）

**现象**：深色主题下，数据分区行「分区1」的容量输入框完全看不见；ESP 的
「300」输入框却有深色底。

**根因（PrintWindow 截图 + 逐像素取样确认）**：三层配色撞车 ——
- `parts_group`（列表容器）底色 = `INPUT_BG()`
- `size_in`（容量输入框，经 `theme::style_input`）底色 = `INPUT_BG()`
- `row_flex` 只调了 `set_color(CARD)`，但 **Flex 默认 `NoBox`，不绘制背景**，
  所以行卡片底色根本没画出来。
=> 取样结果：容器/行/输入框全是 `(43,47,58)`，输入框融进底色。

**修复（2 处，几何零变化）**
- `parts_group` 底色 `INPUT_BG()` → `BG()`；
- 动态分区行 `row_flex` 补 `set_frame(FrameType::FlatBox)`，让 `set_color(CARD())`
  真正绘制出行底色。
形成三层递进：深色 `BG(21,23,30) < CARD(32,35,45) < INPUT_BG(43,47,58)`；
浅色 `BG(245,247,252) / CARD(255,255,255) / INPUT_BG(236,240,248)` 同样可辨。

**验证**：纯 ctypes（`SetProcessDpiAwareness(2)` + `PostMessage` 发
WM_MOUSEMOVE/LBUTTONDOWN/UP + `PrintWindow(PW_RENDERFULLCONTENT)` + GetDIBits）
打开真实对话框截图 —— 该环境 **没有 pywin32**，不要再用 `win32gui`。
深浅两套主题、1366×768 与 800×600 档位均确认输入框可见、无裁切。
验证后已把 `target/debug/config.ini` 的 `theme_mode` 从临时 light 改回 auto。

**发布**：cargo test / cargo test --release 均 100 passed；
`cargo build --release` → `target/release/sks_installer.exe` 2,916,864 字节（11:10），
无源码比产物更新。

**遗留**：上一轮「日志按每天一个文件保存」的需求在中途被打断，
`src/utils/logging.rs` 仍是原状（当天写无日期的 `log/debug.log`，跨天才重命名为

## 「当前方案」显示完整路径 + 自动折行（src/ui/app.rs、layout.rs、README.md）

**原状**：页脚只显示 `Path::file_stem()`（文件名），长路径会被裁切。

**关键技术点**：FLTK 的 `Align::Wrap` **只在空格处折行**（`fl_expand_text`
遇到 `' '`/`'\n'` 才检查宽度），Windows 路径没有空格时会整体溢出，
所以必须自己按像素宽度切分并插入 `\n`。

**实现**
- `current_scheme` 语义改为**完整路径**（"无" 表示失效）；统一入口
  `set_current_scheme(Option<&str>)` / `apply_scheme_label()` /
  `refresh_scheme_label()`（缓存 `scheme_label_w`，宽度变了才重排）。
- 4 个调用点：启动恢复（配置里的路径即使文件不在也显示）、方案失效、
  保存后、加载后；`save_scheme` 的默认文件名改从路径取 `file_stem`。
- 自由函数 `wrap_path_by_width(path, max_w, max_lines, measure)`：逐字符测量，
  优先在 `\ / :` 后断行，最多 `SCHEME_MAX_LINES=3` 行；超出上限才在末行
  用 `…` 收口，完整路径挂 `set_tooltip`。`wrap_scheme_path` 用
  `draw::set_font(ui_font, 10)` + `draw::measure` 提供真实像素测量。
- 窗口缩放：`win.resize_callback` 里 `root.layout()` 之后调
  `App::with(|a| a.refresh_scheme_label())`；`new()` 里 `win.show()` 后
  再按真实宽度重排一次（构建期控件宽度是 0）。
- 布局：`foot_row_h` 正常 30→**44**、紧凑 26→**40**（10px 字 ×3 行 ≈39px），
  `footer_h` 68→82；紧凑档 `min_content_h` 504 ≤510 仍通过 `compact_fits_800x600`；
  `normal_keeps_legacy_heights` 断言同步 68→82。
- README 两处（界面导览、方案保存）改为「完整路径 / 自动折行 / 悬停查看」。

**验证**：cargo test / test --release 105 passed（新增 5 个纯逻辑折行测试）。
纯 ctypes PrintWindow 截图：1366×768 路径一行完整显示；800×600 三行完整
到 `.bat` 无省略号、5 行选项与页脚按钮无裁切；把窗口从 800×600 放大到
2400×1300 后自动重排回一行。验证用的 `plan_path` 长路径已还原为空。

**发布**：`cargo build --release` → `target/release/sks_installer.exe`
2,928,128 字节（11:36），无源码比产物更新。

## 保存方案自动补 `.bat` 后缀（11:57 发布）

**问题**：保存方案对话框里只输方案名（不带 `.bat`）时，写出的文件没有后缀，
「加载方案」的 `*.bat` 过滤器也找不到它。FLTK `BrowseSaveFile` 不会按
`set_filter` 自动补扩展名（不像 Windows 原生保存对话框）。

**实现**（`src/ui/app.rs`）
- 新增纯函数 `ensure_bat_extension(&str) -> String`：空路径原样返回；
  结尾不是 `.bat`（`to_ascii_lowercase().ends_with`）时追加 `.bat`；
  已带 `.bat` / `.BAT` / `.Bat` 原样保留。
- **不用** `Path::set_extension`：方案名常带点（`win11.23h2`），
  `set_extension` 会把点后内容一并替换掉。
- `save_scheme()` 在 `dlg.filename()` → `to_string_lossy()` 之后调用，
  补齐后的路径用于 `std::fs::write` / `cfg.plan_path` /
  `set_current_scheme` / 状态栏 / 日志 / 提示，全链路一致。
- 新增 4 个单测（缺后缀、已有后缀大小写、带点方案名、空路径），
  README 场景 3 补一句「不用手动敲 .bat」。

**验证**：`cargo test` 110 passed + 2 ignored（106 → 110）。本轮只改保存逻辑，
未动布局，故无需两档截图复核。

**发布**：`target/release/sks_installer.exe` 2,929,664 字节（11:57:31），
晚于 `app.rs` 11:56:41 / `README.md` 11:56:48。
