## 修复 800×600 下主窗口「显示不全」

**根因**：主窗口每块都是 `Fl_Flex` 定高，定高之和即内容最小高度。正常档需要
约 814×566 的客户区，而 800×600 屏幕只有 760×510 → 右侧「安装选项」卡片与
「开始安装」按钮被裁掉、「安装完成后重启」等复选框右半截被切；同时窗口最小
尺寸 `size_range(760,560)` 让用户也无法把窗口缩到屏幕内。

**做法**：新增 `src/ui/layout.rs`（`Layout` 结构 = 两档度量 + 窗口几何推算）
- `Layout::normal()`：与改造前完全一致（测试锁定 106/104/168/140/78/119/26/52/68/168）。
- `Layout::compact()`：内边距 10→8、行高 26→24、标题间距 5→4、页头 52→34、
  页脚 68→54、根边距 8→6、左列 320..520 → 260..360。内容 456px、最小宽 714px，
  正好塞进 800×600 的 760×510 客户区。
- `Layout::detect()`：`screen_size()` 可用区（宽-40 / 高-90）放不下正常档即切紧凑档，
  并算出窗口尺寸/居中位置；窗口最小尺寸被钳到屏幕内。
- `app.rs` 全部魔数改用 `lay.*`；`set_gho_mode` / 日志展开 / resize 回调共用同源数值。
- 左列宽度预留量修正为 `right_min(401) + 卡内外边距 + 间距 + 分隔线 + 根边距`
  （旧公式 `w-449` 少算 16px，中间宽度区间右列一直被裁）。
- 日志展开时 `min_main` 额外 `+root_spacing`（日志多出一段横带间距，否则主体被多压 6px）。
- `one_click.rs` 一键分区对话框按 `dh < 600` 切紧凑度量（间距 10→6、行 26→24、
  卡片内边距 10→8 等），8 个分区行 512px 可放进 800×600 的 552px 对话框。

**验证**：临时加过 `SKS_UI_VIEWPORT` / `SKS_UI_DUMP` 调试钩子（已删除），
在伪造视口下导出所有控件几何并检查越界：800×600、1024×768、1366×768、1920×1080
均为 0 处越界；1920 下窗口 1240×840、左列 520、右列 627 与改造前完全一致。
`cargo test` 89 passed（新增 layout 模块 4 个断言测试）。

**注意**：FLTK 的 `Widget::x()/y()` 是**相对窗口**的绝对坐标（`Fl_Widget.H` 注释
"position in its window"），`Fl_Flex::layout()` 直接用 `x()+margin` 定位子控件，
所以遍历控件树时不要再逐层累加父偏移。

## 修复磁盘列表「一键分区」按钮不可用 + 拖横向滚动条时列表错乱

**根因（FLTK tree-as-container 的两个硬伤）**
1. `TreeItem::set_widget` + `LabelAndWidget` 下，`Fl_Tree_Item::draw()` 把控件 x 算成
   `label_x + 实测标签宽 + widgetmarginleft` —— 按钮跟着文字跑，不右对齐。磁盘行标签
   （型号+容量）在 260~306px 的紧凑左列里远超可视宽度，按钮被推到树的右边界之外，
   看不见也点不到。
2. 每次绘制都会 `widget()->resize()` 按滚动偏移重定位控件，`resize` 只给父级打
   `FL_DAMAGE_CHILD`；此时 `Fl_Tree_Item::draw()` 的 `damage() & ~FL_DAMAGE_CHILD`
   不成立 → 条目不重绘、只重绘子控件 → 旧位置按钮像素不被覆盖。拖横向滚动条就是
   一路"幽灵按钮"残影 + 文字被压。

**做法**：新增 `src/ui/disk_row.rs`（`DiskRowUi`，放在 `Rc` 里三方共享）
- 按钮改为**树自绘**：`Tree::draw()` 的 inner_drawer 在 `Fl_Tree::draw()` 之后执行，
  在此按行画圆角 pill（先铺行底色清字形，再画 pill + 描边 + 文字）。
- 位置用 `label_x + label_w`（= 树可见内容区右边界，FLTK 内部即此定义）向右吸附，
  **与标签长度、横向滚动偏移无关**；实测：树收窄到 260 宽 + hposition(120) 后
  `label=(-29,321)` → 右边界仍是 292，按钮 rect 恒在 (232,119,54,14)。
- 命中检测 `DiskRowUi::handle` 用同一套几何（`row_button_rect`），Press 记录、
  Release 校验同按钮才 `RowEvent::Clicked(idx, phys)` → `on_one_click`；Move/Leave 更新
  hover 并 `tree.redraw()`。钩子挂在 `tree.handle`（cfltk `super_handle_first=true`，
  `Fl_Tree::handle()` 先跑，我们的结果按 `ret|local` 合并，不抢树的滚动）。
- 删掉 `disk_buttons: Vec<Button>`、`Fl::delete_widget` 延迟删除、`tree.begin()/end()`
  与 `Group::set_current(None)`、`set_item_draw_mode(LabelAndWidget)`、
  `theme::tree_button`（全部不再需要）。

**验证**：临时 dump（已删除）确认 draw 钩子被调用、按钮矩形落在树可视区内、
`hit_test(按钮中心)` 命中对应磁盘；`cargo build` 干净，`cargo test` 91 passed
（新增 disk_row 2 个几何断言）。**本机无交互桌面（ImageGrab/PrintWindow 均不可用），
视觉仍需在真机/800×600 虚拟机上确认。**

## 修复：悬停树按钮列表变空 + 按下按钮变方形色块（同一根因）

**根因（cfltk + apply_window_backdrop 的交互）**：
cfltk `Widget_Derived::draw()` 默认 `super_draw_first=true`，窗口自绘回调在
`Fl_Window::draw()` **之后**执行。默认绘制结束时已把所有子控件 damage 清零；
局部重绘（FL_DAMAGE_CHILD：按钮按下、tree.redraw 等）时，回调里的
`Fl_Double_Window_draw_children` 走 update_child 分支——没有控件还带 damage，
什么都不画，受损矩形里只剩我们先画的渐变。于是：
- 按下任意按钮 → 按钮矩形 = 纯渐变方块（bug 2）；
- 悬停树行内按钮触发 tree.redraw → 整个树矩形 = 纯渐变（bug 1）。
整窗重绘没事，因为全量分支的 `draw_child` 会 `clear_damage(FL_DAMAGE_ALL)`
强制每个子控件重画。

**修复**：`theme::apply_window_backdrop` 画完渐变后
`w.set_damage_type(Damage::All)` 强制 draw_children 走全量分支——
受损矩形内父级卡片底色、树条目、按钮全部补画完整；屏幕拷贝仍按受损
矩形裁剪（clip region 在 draw 前已设定，不受 damage 标志影响），不闪烁。
一处修复覆盖所有窗口（主窗口/一键分区/重启/消息框都走这个函数）。
`redraw_whole_window` 保留为双保险。

**验证**：cargo build 干净，cargo test 91 passed，启动冒烟无 panic。
无法截图（无交互桌面），视觉效果需真机确认。

## 修复：系统主题识别读错注册表键（src/ui/theme_mode.rs）

**根因**：`detect_system()` 读的是
`HKCU\Software\Microsoft\Windows\CurrentVersion\ContentSettings\AppsUseLightTheme`，

**改动**：路径提成常量 `THEME_SUBKEY` / `THEME_VALUE`（避免再次硬编码走偏），
`detect_system()` 改用常量；新增测试 `subkey_is_themes_personalize` 断言路径与
"不含 ContentSettings"，防回归。

**验证**：启动日志对比 —— 旧代码 16:39 `主题模式: auto（生效: 明亮）`，
新代码 16:50 `主题模式: auto（生效: 深色）`，与注册表 0 一致；
